# 工程文件归置与 GitHub 同步

## 问题（2026-10-29）

> 每次工程有修改就想同步到github，该怎么做，另外现在robot_rl里面很多新增的文件和工程，其实应该可以放在对应的工程下面，比如日志和运行脚本，你对应移动一下看看，因为之后我会做工程的版本管理，比如`/home/newname/文档/Trae-CN/temp_20261022_01/robot_rl/unitree_rl_lab`是从github上clone下来的，那有变化就需要同步到github上去，因此所有工程的变化都要放在工程下，而不是和他同一级

## 回答

### 一、与 GitHub 同步的方法

工作区内共有 4 个 git 仓库，remote 均为 w547 名下，origin 目前已统一为 SSH：

| 工程 | 远程地址 |
|---|---|
| unitree_rl_lab | git@github.com:w547/unitree_rl_lab |
| unitree_rl_mjlab | git@github.com:w547/unitree_rl_mjlab547 |
| unitree_mujoco | git@github.com:w547/unitree_mujoco |
| unitree_sdk2 | git@github.com:w547/unitree_sdk2_547 |

为何用 SSH：gh-proxy.com 镜像对写操作不转发认证（push 返回 401 No anonymous write access），github.com 的 https 直连被墙超时；而 github.com:22 可达，本机 `~/.ssh/id_ed25519` 已绑定 GitHub 账号 w547（`ssh -T git@github.com` 返回 Hi w547）。

每次修改后的同步流程（以某个工程为例）：

```bash
cd <工程目录>
git status                          # 看改动清单
git add -A                          # 或 git add <具体文件>
git commit -m "fix: 说明改了什么"
git push -u origin HEAD             # 推到当前分支（走 SSH，免密）
```

几点约定：

1. 提交说明格式建议 `fix:` / `feat:` / `chore:` 开头。
2. `logs/` 已被两个工程的 .gitignore 忽略（lab 为 `**/logs/*`，mjlab 为 `logs`），日志只留在本地，不进入版本库，不会改变工程源码树。
3. 推送认证走 SSH 密钥，无需 PAT；本机另存了一份 HTTPS 凭据（credential.helper store + ~/.git-credentials）作为备用，但 https 推送在本网络环境下不可用。

为省事，工作区根目录新增了 `sync_github.sh`，一条命令把 4 个工程全部 add/commit/push（无变更自动跳过）：

```bash
./sync_github.sh                          # 默认提交说明
./sync_github.sh "fix: 修复启动时序"       # 自定义提交说明
```

- 运行时机由自己掌握：改完代码 → 跑一下脚本即可；想要更自动化可以后续加定时任务，但自动提交的说明都是通用文案，建议平时还是手动带说明提交。

### 二、工作区文件归置（本次已执行）

原则：工程相关的一切（脚本、日志、入口、变更日志）都放进对应工程目录，工作区根只留跨工程的环境与元信息。

| 原位置 | 去向 | 说明 |
|---|---|---|
| scripts/run_lab.sh、run_lab_click.sh | unitree_rl_lab/scripts/ | 路径自适应：LAB_ROOT=工程根，WS_ROOT=工作区根（../..），env.sh 与 unitree_mujoco 走 WS_ROOT，控制器与日志走 LAB_ROOT |
| scripts/run_mjlab.sh、run_mjlab_click.sh、build_all.sh、build_all_click.sh | unitree_rl_mjlab/scripts/ | 同上拆出 MJLAB_ROOT/WS_ROOT，build_all.sh 里 SDK2 与 env.sh 走 WS_ROOT |
| logs/lab_run_*（10 个） | unitree_rl_lab/logs/ | .gitignore 已忽略 |
| logs/run_*（26 个）、logs/build_*.log（24 份）、MUJOCO_LOG.TXT | unitree_rl_mjlab/logs/ | .gitignore 已忽略 |
| unitree_rl_lab_编译并运行.desktop | unitree_rl_lab/ | Exec/Path 更新为新脚本位置 |
| unitree_rl_mjlab_编译并运行.desktop、编译全部工程.desktop | unitree_rl_mjlab/ | Exec/Path 更新为新脚本位置 |
| CHANGELOG_unitree_rl_lab.md | unitree_rl_lab/CHANGELOG.md | 并补记本次移动 |
| CHANGELOG_unitree_rl_mjlab.md | unitree_rl_mjlab/CHANGELOG.md | 并补记本次移动 |
| （新增） | 工作区根 sync_github.sh | 4 工程一键 add/commit/push |

保留在工作区根（跨工程，不属于单一工程）：`env.sh`（部署环境与依赖路径）、`docs/`、`.screenshots/`、`sync_github.sh`。原工作区根 `scripts/`、`logs/` 已清空删除；`QA/` 记录已按主题归入各工程的 `doc/QA/`（本文件覆盖全部工程与 Git 同步约定，置于 `unitree_rl_lab/doc/QA/`，其余 4 份归入 `unitree_rl_mjlab/doc/QA/`）。

验证：7 个脚本均通过 `bash -n`；脚本引用的工程/目录路径全部存在。未实际启动仿真闭环，仅静态校验。
